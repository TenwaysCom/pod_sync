当前默认模式

  • 默认使用 parse_only 模式：不先查 Odoo Scope，只从 POD 文件信息里识别可回填主键。
  • 识别文本来源包括 file_name、source_path、local_path。
  • 识别结果优先使用 picking_name；没有唯一 picking 时，才使用唯一 tracking_number。
  • 无法确定唯一主键的文件会进入“待处理”，不会进入 Odoo 回传 payload。

通用清洗

  • 所有候选值会转大写，并去掉非字母数字字符，例如 WCB2B/OUT/22114 会规范成 WCB2BOUT22114。
  • 同一个候选只保留一次。
  • 类似 20260430 的日期数字不会当作 tracking number。
  • picking 后面的噪音字母会剥离，例如 WCB2BOUT19782A 识别为 WCB2BOUT19782。
  • 邮政 tracking 的尾部字母会保留，例如 LA857793468NL、CF438625735NL。

CMC OneDrive

  • EU22114.pdf 识别为 WCB2BOUT22114。
  • HK23898.pdf 识别为 WCB2COUT23898。
  • 支持 EU-22114、EU_22114、EU 22114 这类分隔符。
  • 多单文件会拆成多条 payload，例如 EU22080-82-83.pdf 识别为 WCB2BOUT22080、WCB2BOUT22082、WCB2BOUT22083。
  • 单页后缀不拆单，例如 EU22114-1.pdf、23735-2.pdf 仍识别为同一个 POD。
  • 纯数字文件默认按 CMC B2B 出库识别，例如 23735.pdf 识别为 WCB2BOUT23735。
  • 完整出库单号会直接使用，例如 WHOUT15504、WCB2BOUT20655、WCB2C-OUT-23898。
  • 退货和其他类型也会识别，例如 WBB2BRET01301、WCB2BRET01301、WRB2BRET01301、Other07400。

EMTC Google Drive

  • 主要识别 tracking number，例如 2026-03-19_3SYZXG8293874.png 识别为 3SYZXG8293874。
  • 支持 3SHOHR 开头的 tracking，例如 3SHOHR094388273。
  • 支持邮政 tracking，例如 LA857793468NL、CF438625735NL。
  • 也支持常见字母数字 tracking：字母开头、数字开头、以及 8 到 24 位纯数字。

Westerman API

  • 按 Westerman shipment reference 查询，例如 WDB2B/OUT/01358。
  • 仅下载配置为 POD 类型的文档，manifest 以 document ID 作为唯一来源标识。
  • shipment reference 会写入来源路径，并按 WDB2B/OUT/xxxxx 规则识别 Odoo 出库单。

待处理原因

  • NO_IDENTIFIER_FOUND：文件名和路径里没有可用 picking 或 tracking。
  • MULTIPLE_PICKING_CANDIDATES：识别出多个 picking，无法安全拆单，也没有唯一 tracking 兜底。
  • MULTIPLE_TRACKING_CANDIDATES：识别出多个 tracking，且没有唯一 picking 兜底。
  • source_url_missing 只是解析备注：说明源文件链接缺失，不等同于识别失败。
